# 06 — "Open in playground" buttons on SQL fences

Every SQL code sample in the docs gets a button linking into the playground
with that SQL pre-filled.

Depends on: 05 (verify the URL contract against the real implementation before
starting: `<base>/playground.html?sql=<base64url no-pad UTF-8>&db=<id>` — check
`PlaygroundPage.vue`'s param parsing).

## Tasks

1. In `site/.vitepress/config.mts` `markdown.config(md)`: wrap the default
   fence renderer. For fences whose info string starts with `sql` or `sqlite`
   and does NOT contain `no-playground`:
   - render the default fence HTML;
   - append an anchor:
     `<div class="open-in-playground"><a href="<base>/playground.html?sql=<b64>">Open in playground ↗</a></div>`
     wrapped together with the fence in a `<div class="playground-fence">`.
   - base64url-encode `token.content` with Node's
     `Buffer.from(sql, "utf8").toString("base64url")`.
   - Support an optional `db=<id>` in the fence info string
     (e.g. ` ```sql db=us-states `) → adds `&db=<id>` to the href.
   - Use VitePress' configured `base` ("/sqlite-tg/") when building the href —
     inside the fence renderer you don't have `withBase`; hardcode via the
     shared `BASE` const in config.mts. Link target should work in dev too
     (`/sqlite-tg/playground.html` — vitepress dev serves under base as well;
     use `.html`-less `/sqlite-tg/playground?sql=...` if cleanUrls is off —
     match whatever ticket 01 configured; default (no cleanUrls) serves
     `/playground` fine in dev; for the built site GH Pages resolves
     `/playground` → playground.html only with a trailing-slash redirect —
     safest is `playground.html`. Verify with `npm run docs:preview`).
2. Style `.open-in-playground` in `theme/style.css`: small, right-aligned,
   subtle (muted color, appears clearer on hover of the fence block), works in
   light+dark themes.
3. Apply `no-playground` to fences where opening makes no sense (e.g. shell
   output blocks mislabeled as sql, the CTE error example in introduction if
   desired — editorial judgement; most should keep the button).
4. The home page example and api-reference examples (generated by
   `build-ref.mjs`) should get buttons automatically — confirm the generated
   fences use `sql`/`sqlite` info strings.

## Acceptance

- `npm run docs:build && npm run docs:preview`: buttons appear on SQL fences on
  home, introduction, api-reference; clicking one lands on the playground with
  the SQL pre-filled and auto-run.
- A `no-playground` fence renders without a button.
- No hydration warnings in dev console (pure server-rendered HTML, no Vue
  component involved).
